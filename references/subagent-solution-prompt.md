# 子代理提示词：方案生成（Task2）

## 输出约束

1. 输出一份完整可评审的技术解决方案 Markdown 文档
2. 文档仅包含需求分析、改造方案、接口变更、数据结构改动、测试设计，**不输出任何可运行业务代码**
3. 禁止改动项目业务源码、测试代码
4. 若存在上一轮 PR 驳回意见，必须回应最新一条评审问题，针对性优化方案内容

## 方案文档模板

```markdown
---
title: "Issue #{N} 解决方案"
issue_number: {N}
issue_type: Bug | Feature
created: YYYY-MM-DD
updated: YYYY-MM-DD
status: draft | revised
review_round: 1 | 2 | ...
---

# Issue #{N} 解决方案

## 需求分析
- 问题描述
- 根因分析（Bug）/ 能力目标（Feature）
- 影响范围

## 改造方案
- 总体思路
- 详细设计（含接口变更、数据结构改动）
- 修改点清单（编号列表，便于代码阶段逐一对照）

## 测试设计
- 验收测试用例清单
- 边界条件覆盖

## 风险与注意事项
- 兼容性影响
- 性能影响
- 回滚方案
```
